# 发展方向

AVS 专注浏览器语义交互，不内置任务规划、站点解题器或模型推理。能力是否适用于某个场景，由调用方 Agent 根据用户授权、页面和验收要求判断。

## 能力主线

1. **更完整的语义编译**：角色、名字、上下文、状态、允许动作与置信度；重名与不确定结构显式降级。
2. **可解释的组件兼容**：iframe 和复杂编辑器先提供能力与限制证据，再通过隔离夹具完善驱动；不猜测模型输入接口。
3. **可靠执行**：唯一定位、实时 actionability、受信任输入、结果未知不重放；用实际断言而不是派发成功验收。
4. **持久观察与恢复**：固定目标、只读监听、游标、超时和取消；逐步接入宿主 Agent 的事件通知机制。独立采样不是自动恢复模型推理。
5. **上下文效率**：按需读取、分区、变化摘要和有界返回；优先保留正确性与安全信号。
6. **开放接入**：可迁移安装目录、主流 Agent 的技能和 MCP 接口，保持生产运行不依赖 Playwright。

## 验证原则

- 先验证本地夹具与生命周期，再进行用户明确授权的真实网站测试。
- 不用真实不可逆业务证明兼容性，不为执行受限步骤放松安全策略。
- 对比固定来源、任务与登录/代理状态，报告失败和范围变化，保留可追溯证据。
- 不预设 AVS 在所有场景胜出；确定性脚本和 CI 不应仅为使用 AVS 而迁移。
